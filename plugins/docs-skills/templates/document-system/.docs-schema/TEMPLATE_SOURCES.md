# Template research and adaptations

These templates are original adaptations for a single topic work-item history, a separate OpenSpec product contract, and a small number of specialized local records. The sources below informed field choices; their filenames, full content, workflow assumptions, and licenses were not copied into this schema.

| Local type | GitHub source examined | Adopted | Kept out |
| --- | --- | --- | --- |
| `work-item` | [voxel51/fiftyone-skills `WORK_LOG.md` guidance](https://github.com/voxel51/fiftyone-skills/blob/main/AGENTS.md#work_logmd) | Context, completed work, actual commands/results, decisions, next steps, references. An append-only chronological timeline keeps every request and discussion reconstructable. | A single repository-wide log and reverse chronological order, which would mix unrelated topics and make event sequence harder to follow. |
| `decision` | [MADR decision template](https://github.com/adr/madr/blob/develop/template/adr-template.md) | Context, decision drivers, options, chosen outcome, consequences, confirmation, revisit trigger. | Full stakeholder and pros/cons ceremony for every small choice; `lifecycle` already expresses local state. |
| `design` | [Rust RFC template](https://github.com/rust-lang/rfcs/blob/master/0000-template.md) and [OpenSpec spec-driven schema](https://github.com/Fission-AI/OpenSpec/blob/main/schemas/spec-driven/schema.yaml) | Concrete examples, alternatives, risks, non-goals, and open questions. The local design is only for work outside the same OpenSpec scope. | Duplicating an OpenSpec proposal, delta spec, or design in `references`. |
| `plan` | [OpenSpec task template and instructions](https://github.com/Fission-AI/OpenSpec/blob/main/schemas/spec-driven/schema.yaml) | Checkable tasks with dependency, artifact, and verification evidence. | A second task list when OpenSpec owns the change. |
| `tdd` | [flowline-io/flowbot TDD standard](https://github.com/flowline-io/flowbot/blob/master/docs/testing/tdd-specs.md) | Case inventory, observed expected RED failure, minimal GREEN, REFACTOR result, final checks. | Go-specific table-test and fixed case-count rules. |
| `reference-note` | [AI Dev Days source-note method](https://github.com/BradGroux/ai-dev-days/blob/master/docs/research-and-education-method.md) | Separate source facts, inference, conflicts, reuse boundary, source version, and review trigger. | Its education-program approvals and domain-specific governance. |
| `weekly-report` | [Atlassian status-report templates](https://github.com/atlassian/atlassian-mcp-server/blob/main/skills/generate-status-report/references/report-templates.md) | Concise summary, completed/in progress, blocker impact and needed action, next period priorities, source links. | Jira/Confluence publication steps, unverified metrics, and audience-specific duplicate report files. |

OpenSpec's [spec-driven artifact reference](https://openspec.dev/docs/schemas/spec-driven) confirms that proposal explains why, delta specs define changed behavior, design explains how, and tasks track implementation. Product requirements and scenarios therefore stay in OpenSpec's native files. This local schema records the work history and links to those files.

The required sections are intentionally few. Use a short `none` or `not applicable` with a reason when a field does not apply; do not invent evidence to fill a template. If recurring real records show a missing field, increment `schema_version` and migrate explicitly rather than changing the schema through plugin updates.
